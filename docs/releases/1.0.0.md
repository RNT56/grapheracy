# Graphview 1.0.0 Release Notes

Graphview 1.0.0 is the first production-grade release of the self-hosted reviewed knowledge graph: source ingestion,
provenance, graph exploration, cited AI, Attention, approved actions, and active agent context share one auditable
memory and review model.

## Highlights

- Hyper-modern graph exploration through Sigma 3/Graphology, lazy Three.js, deterministic saved layouts, progressive
  clustering, semantic motion, context recovery, keyboard navigation, and an accessible non-WebGL equivalent.
- PostgreSQL/pgvector support for 100,000-node/500,000-edge projects. The accepted immutable-runner p95 values are
  169.3 ms clustered overview, 36.8 ms concrete detail, 21.2 ms focused subgraph, and 12.1 ms hybrid search.
- Continuous upload, URL, GitHub/repository, Google Workspace, and Notion ingestion through durable Arq jobs,
  transactional outbox dispatch, cursors, retries, tombstones, webhook verification, and connector health.
- Planning, cited graph Q&A, scoped research, provider-neutral AI runs, retrieval audits, and review-gated proposals.
- A complete nervous-system loop from signals and observations through owned Attention, reviewed decisions, permitted
  GitHub/SMTP/signed-webhook actions, outcomes, and feedback.
- MCP and VS Code/Cursor active-context capture with ordered offline replay, scoped tokens, redaction, encrypted object
  retention, resumable SSE, and reviewed derivation.
- Generic OIDC/PKCE, Redis sessions, service JWTs, project authorization, CSRF, Vault secret references, strict outbound
  policies, audit records, and OpenTelemetry traces/metrics.
- Hardened Compose and Helm reference deployments plus checksummed backup/restore, SBOMs, image scans, provenance,
  Cosign signatures, Sigstore checksum bundles, and signed release publication.

## API Compatibility

- `/api/v1` is canonical.
- Existing unversioned routes remain compatibility aliases through Graphview 1.1 and return deprecation, sunset, and
  successor-link headers.
- FastAPI/Pydantic OpenAPI is the wire source of truth; the committed TypeScript client is generated and drift-checked.
- Existing IDs, provenance, review decisions, and graph entities are preserved through migration.

## Upgrade And Recovery

1. Capture and verify a production backup before changing images.
2. Run the Alembic migration Job against the expand-compatible schema.
3. Deploy the immutable image digests from the release manifest.
4. Verify `/health`, `/ready`, OIDC login, authenticated upload, durable worker completion, review visibility, and
   OpenTelemetry export.
5. Keep the previous image set available for application rollback; do not reverse destructive migrations.

Production restore never restores Vault. It removes connector, provider, action-adapter, and active-context credentials,
revokes sessions/clients, suppresses queued side effects, flushes Redis, and requires explicit reauthorization after
validation. Restore is for verified corruption, not routine application rollback.

## Deployment Artifacts

- Eight immutable container images: web, API, worker, Collector, ops, Keycloak, ClamAV, and MinIO.
- `graphview-agent-gateway-1.0.0.tgz`.
- `graphview-active-context-1.0.0.vsix`.
- SPDX 2.3 client artifact SBOM, image SBOM/provenance, image digest manifest, release manifest, SHA-256 list, and
  Sigstore checksum bundle.
- Compose and Helm reference deployments, including migration and backup jobs.

## Scope

Graphview 1.0 targets a single internal organization with multiple projects. Public multi-tenant SaaS, a separate graph
database, and an open-source licensing decision are outside this release. PostgreSQL remains the graph system of
record; 2D remains the default operational view, while 3D is a semantically equivalent exploration mode.
